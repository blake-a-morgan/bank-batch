=====================================================================
 CUSTPRT - CUSTOMER BALANCE REPORT : LAYOUT AND EXPECTED OUTPUT
=====================================================================

DESIGN DECISIONS
----------------
Break field : CUST-ACCT-STATUS (A = active, F = frozen, C = closed)
              Not state: every test customer is in a different state,
              so a state break would make a "group" of one customer
              each time and would not really test the break logic.
Sort order  : status, then account number (DFSORT step before the
              program - the KSDS itself is in account-number order)
Columns     : account, name, state, balance, credit limit,
              last activity date
Totals      : per status group - account count and total balance
              grand total     - account count and total balance,
                                plus counts for active/frozen/closed
Line width  : 132 print positions (only 1-95 used)

FIELD SIZES (so totals cannot overflow)
---------------------------------------
Customer balance  S9(7)V99  -> edited  Z,ZZZ,ZZ9.99-        (13 chars)
Credit limit      S9(7)V99  -> edited  Z,ZZZ,ZZ9.99         (12 chars)
Total balance     S9(11)V99 COMP-3 accumulator
                            -> edited  ZZ,ZZZ,ZZZ,ZZ9.99-   (18 chars)
                  Room for up to 99,999,999,999.99 - enough for
                  10,000 customers at the maximum balance each.
Account counts    9(5)      -> edited  ZZ,ZZ9 / ZZZZ9

CONTROL BREAK RULES
-------------------
1. Print headings at the top of every page (and on page 1).
2. When the status changes: print the previous group's total line,
   reset the group count and group balance, then process the record.
3. At end of file: print the LAST group's total, then the grand totals.
4. Group totals roll into the grand total.
